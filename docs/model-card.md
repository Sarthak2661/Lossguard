# LossGuard model card

## Current local artifact

The figures below come from the tracked `models/model_metadata.json` generated by a bounded
training run; retraining can produce different values. Recreate the ignored binary with
`docker compose --profile tools run --rm trainer` after validating the supplied dataset.

- Model version: `xgb-calibrated-20260822T085526Z`
- Training source/cap: first 300,000 timestamp-ordered rows of `fraudTrain.csv`
- Windows: 210,000 training; 45,000 calibration; 45,000 threshold validation
- Calibration: isotonic regression fitted only on the calibration window
- Independent final test: all 555,719 rows of `fraudTest.csv`
- Final-test fraud rate: 0.386%
- Final-test ROC AUC / average precision: 0.9936 / 0.7942
- Final-test Brier score / log loss: 0.00138 / 0.00630
- Global cost thresholds: verify at 0.05, decline at 0.45
- Final-test simulated policy cost: $227,653.82
- Final-test approve-all simulated baseline: $1,133,324.68

The machine-readable windows, calibration metrics, category thresholds, feature names, decisions,
and checksum are in `models/model_metadata.json`. The binary bundle is ignored by Git and must be
paired with its locally generated `.sha256` sidecar.

## Intended use

This model supports local, retrospective analysis of approve, verify, and decline policies. It is
not approved for payment authorization or customer treatment.

## Evaluation and reliability caveats

- `fraudTest.csv` is used once as an independent final-test window and is also the historical replay
  source; displayed dashboard outcomes are therefore retrospective, not production generalization.
- Producer-side schema failures are currently logged and skipped before Kafka, so they do not
  appear in the consumer's dead-letter table. The offline final-test loader does not apply that
  replay schema filter, so the evaluation and replay populations are not identical.
- The source data is synthetic and dated 2019–2020; its behavior may not represent a current merchant.
- Threshold results depend directly on documented margin, reacquisition, verification, and
  abandonment assumptions.
- Calibration reduces probability error on these windows but does not guarantee calibration after
  distribution shift; stale/error drift status must be treated as an operational warning.
- SHA-256 detects mismatch against a local sidecar, not publisher identity. The `joblib` bundle is a
  trusted-local-only artifact and must never be loaded from an untrusted upload.
- Production use requires delayed-label handling, fairness/privacy review, signed model promotion,
  independent validation, production IAM/TLS, and capacity/availability engineering.
